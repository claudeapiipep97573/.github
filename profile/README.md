<h2>一、把挑拆成五个可打分的问题</h2>
<p>选型之所以拖很久，是因为问题问得太虚。稳定性怎么样这种问法，任何销售都能答很稳。换成一组可以量化、可以验证的问题，比较就会变得很快，也更容易在两家之间做决定。</p>
<h3>问法决定答案质量</h3>
<p>好问题的标准有三条：答案是一个数或一个明确承诺、能写进订单备注、事后可以验证。比如这条地址同时允许几个账号登录，就比这条地址稳不稳强得多。前者答不上来就是有问题，后者永远能得到一个让人安心的回答。</p>
<h3>五个问题的具体问法</h3>
<p>一，这条地址独占的是整段、单条还是端口，同 C 段已售出多少条；二，固定是合同固定还是技术固定，地址变更会不会提前通知；三，并发上限按连接数、每秒请求数还是端口数算，具体数值多少；四，替换是否免费、每月几次、工单多久生效；五，能不能按真实请求模型跑满 24 小时试用。五条都能给出具体答案的供应商，通常管理也比较规范。</p>

<h2>二、固定出口：先确认是不是真的固定</h2>
<p>固定是这类产品最容易被模糊处理的词。三种情况都叫固定，但对业务的影响完全不同，谈价格之前先把定义对齐。</p>
<h3>合同固定：写进条款的才算</h3>
<p>地址变更需要提前通知、变更后的补偿方案、变更频率上限，这三条写进合同或订单备注，才有约束力。只写在宣传页上的长期固定，出问题时没有依据。实践中最常见的纠纷，就是上游网段调整导致地址静默更换，而合同里没有任何相关约定。</p>
<h3>技术固定：看租期与上游策略</h3>
<p>有些地址通过静态绑定下发，只要上游不做网段调整就不会变；有些是长租约分配，理论上会变。问清是哪种，比听承诺更实在。你也可以自己每周记录一次出口地址做比对，连续四周不变，才算技术上也稳定。</p>
<h3>地区固定：国家、城市、ASN 三层</h3>
<p>业务说要美国地址，实际可能需要的是特定城市的住宅段。三层都固定，才谈得上地区一致性；只固定国家，城市漂移照样会让账号资料看起来矛盾。核对时用公开的归属库查国家与城市，再用 ASN 确认是否属于住宅运营商。</p>

<h2>三、并发上限：三种口径别混着比</h2>
<p>两家报价单上写着同样的支持一百并发，实际能力可能差三倍，因为口径不同。比较之前先统一口径，否则比的是数字，不是能力。</p>
<h3>连接数口径</h3>
<p>指同时保持的 TCP 连接数量。长连接场景下这个数字最接近真实约束，但它不限制每秒请求数，一条连接上可以跑很多请求。如果你的业务是长连接加低频请求，看这个数就够了。</p>
<h3>请求数口径</h3>
<p>指每秒或每分钟允许的请求次数。短连接、高频调用场景更该看这个。注意有些供应商按分钟计，把数字写得很大，换算成每秒其实很有限，问的时候要追问单位。</p>
<h3>端口口径</h3>
<p>指分配给你的代理端口数量。端口多不等于并发高，但端口少一定限制并行。多账号场景里，端口数往往才是真瓶颈，因为一个账号通常要绑定一个固定端口才能保持出口不漂移。</p>

<h2>四、打分表怎么用：权重与淘汰线</h2>
<p>打分表的价值不在于算出一个总分，而在于逼你把注意力放在能验证的项上。用起来有两个规则：先过淘汰线，再比总分；任何一项触及淘汰条件，直接出局，不参与后续比较。</p>
<h3>先淘汰，再排序</h3>
<p>淘汰条件是不接受谈判的底线。比如拒绝把变更通知写进订单，这一条不因为价格便宜而妥协。实践中最常见的错误是便宜就忍了，结果半年内换了三次地址，人力成本早就超过省下的钱。</p>
<h3>总分只用于二选一</h3>
<p>当两家都过线、价格接近时，总分能帮你决定。差距在五分以内，说明两者水平相当，这时候应该看售后响应速度，而不是继续抠参数。把打分表留档，半年后复盘时它能告诉你当初为什么选它，以及哪一项判断错了。</p>

<h2>五、谈价与验收的分界点</h2>
<p>谈价和验收是两件事，混在一起谈会失去筹码。正确顺序是先确认能力，再谈价格，最后用验收结果锁定长期合作。</p>
<h3>能力确认阶段不谈折扣</h3>
<p>这个阶段只问参数和政策，让对方知道你懂行。过早问折扣，会让对话重心跑到价格上，关键条款反而被跳过。价格谈判的锚点是明确的账号数量和流量预估，含糊地说以后量会很大，换不来真实折扣。</p>
<h3>验收通过再谈长约</h3>
<p>先用一个月验证：地址是否真的不换、晚高峰是否稳、工单响应是否守时。三项都过，再谈年付。反过来先签年付再验收，主动权就没了，而且年付折扣通常绑定锁定期，中途退出要付代价。</p>

<h2>常见问答</h2>
<h3>独享住宅 IP 一定比共享的稳吗？</h3>
<p>答：不一定。独享排除的是他人同时占用这个变量，但地址本身的历史记录、上游线路质量仍然起作用。独享是必要条件，不是充分条件，仍然要做纯净度和延迟验证。</p>
<h3>并发上限可以后期加吗？</h3>
<p>答：通常可以，但要看上游资源。加并发往往意味着换套餐或加端口，价格不一定线性。签合同前把半年后的预估量告诉对方，问清扩容的价格阶梯，比事后临时加要便宜。</p>
<h3>试用期该测什么？</h3>
<p>答：测三件事——地址在 24 小时内是否发生变更、晚高峰的延迟与丢包、按真实请求模型跑满时的错误率。只测能不能连通，等于没测。</p>
<h3>供应商说要审核资质才能开，正常吗？</h3>
<p>答：属于常见做法。正规服务商需要确认用途与主体信息，这本身是合规要求的一部分。遇到完全不问用途、只催付款的，反而要多留个心眼。</p>
